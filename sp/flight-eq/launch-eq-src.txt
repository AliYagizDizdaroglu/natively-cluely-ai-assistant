## Source text of launch-eq.cmd and launch-eq-dry.cmd (PREREGISTER-flight-eq.md section 2 and 7.b7; AMENDMENT-A2.10 P7, A4.6, A5.2, A6).
## Read by gen-launchers-eq.mjs only. A line starting with two hash signs is a note for the reader and is dropped. A line of the form
## "=== name ===" starts a section. Macros {{LABEL}} {{LOG}} {{ERR}} {{NODE}} {{PROOFS1}} {{PROOFS2}} {{PASSES}} {{COMMIT}} {{T}} are expanded by the generator;
## nothing else is. The result is ASCII with CRLF line ends and is read back byte by byte by the generator itself.
## launch-eq.cmd = head-flight + common + guard-flight + tail-flight. launch-eq-dry.cmd = head-dry + common + guard-dry + tail-dry.
## The two guard sections differ by one argument and nothing else: the real launcher passes --require-precheck.
## Style rule that cost a flight once: no parentheses, ampersand, pipe, caret or percent sign inside any echo of an if-block, and no rem line holds one either.
## %~dp0 is the folder of the launcher itself: the helpers sit beside it (E), the run happens with the working directory MAIN.

=== head-flight ===
@echo off
rem Flight eq, task Natively-flight-eq: the earlier-question hour, NATIVELY_EARLIER_QUESTION=1 on scenario50 S1 and S2 on MAIN at the registered HEAD.
rem Registration PREREGISTER-flight-eq.md, section 2, with amendments A1 to A6. ONE change under test: the earlier-question block. Everything else is the shipped default: the verbal hedge is ON because its variable is cleared, no follow-up parent, no model or thinking override, Deepgram plus the Live ear, the focused Flash arms OFF by NATIVELY_FLIGHT_FOCUSED=off.
rem Generated by gen-launchers-eq.mjs from launch-eq-src.txt. Never edit this file by hand and never with sed: change the source text and re-run the generator, which reads the bytes back.
rem NATIVELY_FLIGHT_COMMIT and NATIVELY_EQ_T below hold PLACEHOLDERS until the controller arms the launcher: node gen-launchers-eq.mjs --commit followed by the registered HEAD hash and --t followed by the task time. Both are checked: the commit here, T by the guard.
rem Knowledge mode ON is a persisted setting, not an environment variable: guard-eq.mjs reads it from the settings file.
rem Error log: natively-eq-launcher-error.log in the TEMP folder must not exist at arming. Launcher log: interview60.runs, flight-eq.launcher.log, in MAIN.
rem Exit codes: 9 wrong folder, 8 audio missing, 7 roster missing, 6 harness does not stop the app, 12 commit not a full hash, 14 committed texts missing at HEAD, 5 wav:check failed, 3 dist proofs failed before or after the run, 4 guard failed. After all of those the exit code is the flight's own.
rem The real guard line passes --require-precheck: without a fresh PRECHECK OK line from the precheck task the guard refuses and the hour does not fly.
rem NOTE ON STYLE: no parentheses inside any echo in an if-block. On 2026-09-20 a guard message citing a commit in parentheses closed its own if-block early, so the exit after it ran unconditionally and a flight died before takeoff with no log of any kind.

=== head-dry ===
@echo off
rem DRY RUN twin of launch-eq.cmd, task Natively-flight-eq-dry: the same preconditions, environment block, commit check, committed-text shas, wav:check, dist proofs and behavioural guard, then it stops. No flight, no app, no audio, no API call.
rem Generated by gen-launchers-eq.mjs from launch-eq-src.txt. The flight launcher and this one are composed from the same common section, so they cannot drift apart. Never edit this file by hand and never with sed.
rem Its GUARD OK line and its NIGHT GATES OK line are required before the real task is registered. The precheck task starts this task itself and reads its log.
rem Same placeholder rule as the flight launcher: node gen-launchers-eq.mjs --commit followed by the registered HEAD hash and --t followed by the task time.
rem Exit codes are the flight launcher's steps before the flight: 9, 8, 7, 6, 12, 14, 5, 3, 4, and 0 when every check passed. This guard line does not pass --require-precheck: no precheck exists yet when the dry twin runs.
rem NOTE ON STYLE: no parentheses inside any echo in an if-block, see launch-eq.cmd.

=== common ===

  exit /b 8

  exit /b 7

rem Guard: the harness must stop the app when a run ends - 5952b23.

  echo the harness does not stop the app when a run ends - pick 5952b23 into this checkout >> {{ERR}}

rem The commit check: 40 lowercase hex characters, nothing else. An unfilled placeholder, a short hash, a long one and an uppercase one all fail here, before anything runs. findstr cannot count to 40 in a pattern, so the length is tested by substring.
set COMMIT_OK=1
echo %NATIVELY_FLIGHT_COMMIT%| findstr /R /X "[0-9a-f][0-9a-f]*" >nul 2>&1
if errorlevel 1 set COMMIT_OK=0
if "%NATIVELY_FLIGHT_COMMIT:~39,1%"=="" set COMMIT_OK=0
if not "%NATIVELY_FLIGHT_COMMIT:~40,1%"=="" set COMMIT_OK=0
if "%COMMIT_OK%"=="0" (
  echo NATIVELY_FLIGHT_COMMIT is not a full 40 character hash - the placeholder was not filled in - run gen-launchers-eq.mjs with the commit >> {{ERR}}
  exit /b 12
)
echo === LAUNCHER {{LABEL}} start %DATE% %TIME% commit %NATIVELY_FLIGHT_COMMIT% T %NATIVELY_EQ_T% === >> {{LOG}}
rem The committed texts, FIRST: the sha256 of each passes file as committed at HEAD, then the arming record's sha256 or ARMING absent. The dry run precedes the record, so absent is not an error here; the precheck gates on the record, and the result note quotes these lines.
{{NODE}} "%~dp0eq-sha-lines.mjs" --root "%CD%" --passes "{{PASSES}}" --arming "%~dp0ARMING-flight-eq.md" >> {{LOG}} 2>&1
if not "%errorlevel%"=="0" (
  echo a committed text is missing at HEAD - see flight-{{LABEL}}.launcher.log >> {{ERR}}
  exit /b 14
)
rem Guard: the audio must hold exactly the roster's clips and gaps.
{{NODE}} electron\test\golden\interview60.run.mjs wav:check >> {{LOG}} 2>&1
if not "%errorlevel%"=="0" (
  echo scenario50.wav does not match the scenario50 roster - see flight-{{LABEL}}.launcher.log >> {{ERR}}
  exit /b 5
)
rem Dist proofs 1: the cue build markers, the four earlier-question markers with the sha256 of earlierQuestion.js, and parity-dist against MAIN's dist, all printed into the log. The root is passed as the current folder in full: dist-proof.mjs fails on a relative root such as a single dot.

{{PROOFS1}} >> {{LOG}} 2>&1
if not "%errorlevel%"=="0" (
  echo dist proofs 1 failed - see flight-{{LABEL}}.launcher.log >> {{ERR}}
  exit /b 3
)

=== tail-flight ===
rem The flight itself. It stops the app by itself when it ends: process.on exit appStop, 5952b23.
