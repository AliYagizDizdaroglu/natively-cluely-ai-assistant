#### ITEM 3 key=S1Q04 topic=Churn prediction level=coding kind=spoken
Q: Let's do some code: implement evaluation for a fixed campaign budget. Write a function called evaluate top k, taking true labels, scores, and k, that returns precision at k, recall at k, and lift over the population prevalence. Assume binary labels and finite scores, and break score ties by original row order. Tell me what it does for an invalid k, for empty inputs, and when there are no positive labels.
A [260 words]: Implement evaluate_top_k by sorting indices by score descending, breaking ties by original row order. Extract the top k$ indices. Calculate precision_at_k as the count of positives in the top k$ divided by k. Calculate recall_at_k as that same count divided by the total number of positives in the full dataset. Calculate lift as precision_at_k divided by the population prevalence, which is total positives divided by total samples.

For invalid k$ (less than 1 or greater than total samples), raise a ValueError. For empty inputs, return zeros for precision and recall, and one for lift, assuming a non-empty denominator for prevalence. If there are no positive labels, return zero for precision and recall, and one for lift, since the population prevalence is zero, making the lift undefined but conventionally set to one to indicate no lift.

import numpy as np

def evaluate_top_k(true_labels, scores, k):
    n = len(true_labels)
    if n == 0:
        return {"precision_at_k": 0.0, "recall_at_k": 0.0, "lift": 1.0}
    
    if k < 1 or k > n:
        raise ValueError("k must be between 1 and the number of samples")
    
    # Sort indices by score descending, ties broken by original row order (ascending index)
    # np.argsort is stable, so we sort by -scores to get descending order
    sorted_indices = np.argsort(-scores, kind='stable')
    top_k_indices = sorted_indices[:k]
    
    top_k_labels = true_labels[top_k_indices]
    total_positives = np.sum(true_labels)
    
    if total_positives == 0:
        return {"precision_at_k": 0.0, "recall_at_k": 0.0, "lift": 1.0}
    
    hits = np.sum(top_k_labels)
    precision_at_k = hits / k
    recall_at_k = hits / total_positives
    population_prevalence = total_positives / n
    lift = precision_at_k / population_prevalence
    
    return {
        "precision_at_k": precision_at_k,
        "recall_at_k": recall_at_k,
        "lift": lift
    }

A [139 words]: I’d treat this as a dual-write migration. First, I’d register the new embedding model version in the vector store, keeping the old one active. Documents get written to both the old and new indexes during the transition, so live updates stay synchronized.
